# Промт для продолжения проекта NEON HOOK

Продолжаем разработку браузерной one-touch аркады **NEON HOOK** под Яндекс Игры (WebGL). Соло-разработка, JS без фреймворков, canvas 2D + Web Audio API. Проект на GitHub: `AshNaMassu/Hook`, рабочая ветка `js-gameplay`.

---

## Что это за игра

Вертикальный endless-свинг с управлением одной кнопкой. Герой падает/летит, игрок **держит** экран — герой цепляется к ближайшей точке и **вращается по окружности** вокруг неё. **Отпускает** — герой срывается и летит по касательной. Задача: подниматься по цепочке точек, собирать монеты, избегать шипов, не дать лаве настигнуть.

**Оси мастерства (две, не одна):**
- **Окно отпускания** (куда полетишь) — отпускать когда скорость направлена к следующей точке;
- **Тайминг зацепа** (сила полёта) — ранний зацеп = длинная верёвка = большая линейная скорость (`v = ω·r`).

**Формула кор-лупа:** `тап → вращение → релиз → полёт → едва не умер → ещё раз`.

```
    ├── fx.js               ← burst (частицы), addFloat (всплывающий текст)
    ├── bot.js              ← botThink — аттракт-режим в меню
    ├── step.js             ← stepWorld(dt) — фиксированный шаг 1/240, физика, камера v2, лава
    ├── render.js           ← drawBG, drawCoin, drawSpike, drawAnchors, drawHero, drawRope,
    │                         drawTrail, drawLava, drawBGParticles, drawDanger, drawVignette,
    │                         render() с bloom-пайплайном
    ├── ui.js               ← DOM-контроллер, hudSync, buildSkins, startRun/toMenu/pauseGame,
    │                         обработчики слайдеров громкости/тряски/вспышек (через классы)
    ├── input.js            ← pointerdown/up → pressAction/releaseAction + клавиатура
    └── main.js             ← requestAnimationFrame с аккумулятором dt, HSTEP=1/240, slow-mo
```

**Ключевые паттерны:**
- Все draw-функции принимают параметр `c` (контекст) с fallback `c = c || ctx` — это позволяет рендерить сцену **дважды** (на bloomCtx и на основном ctx) для bloom-эффекта через offscreen canvas + `ctx.filter = 'blur(...)'`.
- Генератор и рантайм используют **один и тот же** `FlightHits()` — единый источник правды: если точка «долетима» по генератору, то и в игре долетима.
- `ReachQuality()` — перебор 16 фаз × 3 ω × 2 r (96 итераций) для оценки ширины окна; порог `q>=0.04 && qm>=1` фильтрует «тесные» раскладки.
- `mulberry32(seed)` — детерминированный PRNG для сидов; daily-сид = дата, «реванш» = lastSeed.

## Что уже сделано (рабочее)

### Ядро механики
- Захват с продолжением момента: `w = (dx*vy - dy*vx) / r²`, если |w| > 0.5 → продолжаем направление; иначе используем `anchor.spinDir` от генератора.
- **Пол ωMin** — нет «нулевой орбиты» (зависание), всегда есть вращение.
- **Потолок ωMax** — окно не становится нечеловеческим.
- **Исключение `lastAnchor`** — нет случайных дабл-зацепов (но полный запрет, не кулдаун).

### Генератор
- `CanonicalShot` — ставит точку туда, куда долетает идеальный выстрел из канонической фазы (315°/225°).
- Монеты всегда на канонической траектории → собираемость гарантирована.
- Шипы — вне траектории, не ближе 1.9 от канонического пути, не ближе 3.8 от точек.
- **Биты маршрута:** calm/tension/bonus/rest; `pickSide` — 70% чередование / 20% серия 2 / 10% серия 3.
- Минимальные зазоры `minDx/minDy` масштабируются от grabRadius — нет «лесенок в одну линию».

### Звук (аудио-система с секвенсором)
- **SFX**: grab/release/coin/perfect/death/ui/deny через синтез (oscillator + noise + filter).
- **Музыка**: секвенсор 122 BPM, 64 шага = 4 такта, прогрессия Am-F-C-G.
- **Два режима**: `'menu'` (только пад + редкие ноты + дрон) и `'game'` (полный состав).
- **Fade-слои** вместо порогов — кроссфейд:
  ```js
  MUSIC_LAYERS = {
    bass: [0.02, 0.3],
    kick: [0.02, 0.35],
    hat:  [0.2,  0.55],
    clap: [0.35, 0.7],
    arp:  [0.02, 0.3]
  }
  _fade(I, a, b) { return clamp((I-a)/(b-a), 0, 1); }
  ```
  Бит проявляется плавно со второго метра, без «щелчка».
- **Динамика**: `intensity = clamp(runT/90 + maxAlt/120, 0, 1)`, растёт со временем и с высотой.
- **Раздельные громкости**: musicVol (множитель 0.65 + 0.25·I), sfxVol (через sfxGain).

### Визуал
- **Bloom**: offscreen canvas половинного разрешения → рендер сцены → overlay с `blur(8px) alpha=0.6` и `blur(16px) alpha=0.3` через `globalCompositeOperation='lighter'`.
- **Пульсация точек**: два расходящихся кольца при входе в grabRadius (момент максимальной силы).
- **Золотое кольцо**: подсветка точек, до которых релиз «сейчас» долетит (по `FlightHits`).
- **Трейл**: двухслойный (glow + ядро), яркость ∝ мощности.
- **Верёвка**: толщина ∝ `power = ω·r`.
- **Фоновые частицы**: 40 плавающих квадратов, респаунятся снизу при выходе из кадра.

### Настройки (сохраняются в localStorage)
- 🎵 Музыка (громкость)
- 🔊 Эффекты (громкость)
- 📳 Тряска (shakeIntensity: множитель к `shakeT * 15 * dpr`)
- ✨ Вспышки (flashIntensity: множитель к `perfectFlash * 0.5`)
- Слайдеры через **классы** (`.musicVolSlider`, `.sfxVolSlider`, `.shakeSlider`, `.flashSlider`) — одинаковые элементы в меню настроек и в меню паузы, синхронизируются.

### Камера v2 + Лава (разделение ролей)
- **Камера = окно**: плавно следует за героем, `lookahead = -1.5` (герой выше центра экрана, вне зоны пальца).
- **Лава = палач**: `lavaY` поднимается со скоростью `baseSpeed + speedRamp·diff` (0.8 + 1.4·diff).
- **Резиновая лента**: если `hero.y - lavaY < LAVA.rubberBand (3)`, камера тормозит на 45% — даёт шанс камбэка.
- **Смерть**: `hero.y < lavaY - LAVA.killMargin (0.5)`.
- **Визуализация лавы**: красная линия с shadowBlur=20 + свечение-градиент + красная рамка по периметру при `dangerLevel > 0.3` (расстояние <5 юнитов).

### UI/UX
- Меню с кнопками «Играть», «Настройки», списком скинов (4 шт.), кошельком, рекордом.
- Экран настроек (отдельный screen) + те же настройки в меню паузы.
- Экран смерти: счёт, монеты, комбо, «Ещё раз», «Тот же маршрут» (реванш через lastSeed), revive за rewarded.
- Аттракт-режим: бот играет в меню (`botThink` ловит ближайшую точку в радиусе, отпускает по FlightHits).
- Onboarding через подсказки (первый зацеп, первый релиз, момент вспышки) + круг радиуса захвата + полная траектория релиза только на первых 3 зацепах.

## ГДД v2 — актуальный контракт физики

```
орбита:   pos = anchor + (cosθ, sinθ) * r
касательная (против часовой): t = (-sinθ, cosθ)
релиз:    vel = t * (spinDir * ω * rPower) + (0, upAssist)
полёт:    vel.y -= g * dt;  pos += vel * dt
зацеп:    |pos - anchor| < grabRadius, exclude lastAnchor
```

**Профиль по умолчанию (PF):**
```
grabRadius 3, rMin 1.2, rMax 3
wMin 3, wMax 6.5, spinAccel 2.5, momThreshold 0.5
g 14, upAssist 1
rNorm 2.1, normalizePower false (тумблер)
lookahead -1.5
```

**Окна отпускания:**
| Вращение | Вверх-вправо | Вверх-влево |
|---|---|---|
| spinDir +1 | 270–360 | 0–90 |
| spinDir −1 | 90–180 | 180–270 |

**Ось силы:** v = ω·r (ранний зацеп = дальний полёт). Тумблер `normalizePower` превращает в v = ω·rNorm (константа), но сейчас выключен.

## Почему принято ключевое решение

- **Вращение, а не маятник**: маятник мог затухнуть в висение, что ломает казуалку. Принудительное вращение + рампа ω = предсказуемый ритм.
- **Пол ωMin, а не кулдаун на повторный зацеп**: кулдаун мешает «осознанной раскачке» (упал → перезацепился с длиннее верёвкой → сильнее полёт).
- **Лава вместо смерти от камеры**: разделение «окно»/«палач» даёт честные камбэки и делает угрозу видимой.
- **Классы для слайдеров, не ID**: один set слайдеров синхронизируется в меню и паузе без дублирования кода.
- **Fade-слои, не пороги**: музыка расцветает плавно, без «щелчков» при смене интенсивности.
- **Единый FlightHits**: нет рассинхрона между «игра обещает» и «генератор построил».

## Текущее состояние и известные проблемы

**Работает стабильно:**
- Ядро свинга, генератор, bloom, звук, лава, настройки.
- Игра играбельна, есть ритм и драйв.

**Под вопросом (авторские заметки игрока):**
1. **Слишком ярко в неоне** — вспышки точек бьют по глазам; ползунок `flashIntensity` есть, но дефолт 100% агрессивен.
2. **Тряска при смерти слишком долгая** — `shakeT=0.85` многовато, дефолт `shakeIntensity` можно снизить до 0.7.
3. **Стена ~50 м** — сложность душит среднего игрока; патчи были предложены (рампа камеры 180 вместо 120, шипы позже, мягче зазоры, выше q-порог) — частично применены, нужно балансировать дальше.
4. **Зацепы у краёв экрана** — герой уходит за экран, приходится ориентироваться по вспышкам; предлагался горизонтальный follow-камеры (`camX` следит за hero.x с клампом), но **не применён**.
5. **Запрет повторного зацепа к той же точке** — ломает раскачку; нужно вернуть через кулдаун 0.2с.
6. **Музыка в меню стартует только на первом pointerdown** (autoplay policy) — это норма, но надо помнить.

## Технический долг и предостережения для нового чата

- `step.js` и `render.js` используют **глобальные переменные** (`hero`, `anchors`, `camY`, `lavaY`, `state`, `dying` и т.д.) из `state.js` — это осознанный выбор для скорости прототипирования, но рефакторинг в модули/классы будет болезненным.
- `FindObjectsOfType`-подобные обходы массивов в hero.js/gen.js — потенциальная оптимизация через индексы/пулы.
- `localStorage` синхронный и блокирующий — при миграции на `ysdk.getPlayer().getData()` нужно делать async-обёртку.
- Bloom через `ctx.filter='blur()'` не работает в старых Safari — нужна проверка совместимости перед публикацией.
- **Порядок `<script>` в index.html критичен**: config → storage → audio → canvas → state → gen → world → hero → camera → fx → bot → step → render → ui → input → main.
